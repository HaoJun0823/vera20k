# 军队规模的实测：产量不是瓶颈，但"再加一座车厂"也不是解法

写于 2026-11-04 05:15，05:25 修正。上一轮的结论「军队没有冗余」是对的，但
**原因**还没找到。

## 数据（同一个 1v7 对局，存活到 24000，own 84）

| 量 | 值 |
|---|---|
| 全场累计出场的单位 id | **133** |
| 最后存活的士兵 | **70** |
| 最后 `own` 对象数 | 84 |
| 工厂 | 1 兵营 + 1 车厂 |
| 22800 tick 时的钱包 | **2360 元，花不出去** |

## 结论一：产量不是"军队小"的原因

房子造了 133 个单位。上一轮我看到"84 个对象"就判断军队小，那是**存量**不是产量。

## 结论二：加第二座车厂**害大于利**（这是修正）

把建造链从"最多一座车厂"改成"最多两座"，实测：

| | 一座车厂 | 两座车厂 |
|---|---|---|
| 1v7 `own` | **84** | **39** |
| 累计单位 | 133 | **71** |

第二座车厂花掉了钱和建造时间（它是 2000 元 + 建造场排队），而累计产量反而
**掉了一半**。所以瓶颈不在车厂数量，我这条推测是错的。

## 结论三：钱包溢出是真的，但原因不明

22800 tick 时有 2360 元花不出去。可能是：
- 两个工厂都在忙（但第二座车厂没有改善，说明这不是全部）
- 或者策略在某处停止了提议（`shortfall` 认为角色配比已经满足）

**后者更可能**：`shortfall` 比较的是**角色配比**，不是绝对数量。如果配比达标，
策略就不再有购买的理由，钱就留着。这不是产能问题，是**策略认为军队够了**。

## 下一步

1. **查 `shortfall` 的判定**：确认它是不是在"配比达标"时就停止购买。如果是，
   需要给它一个绝对下限（比如"士兵少于 N 就一直买"）。
2. 别再加工厂——已测，有害。
3. 存活率（133 造出、70 活着）是另一个方向，还没查。

## 不该做的事

- 不要提高矿车或精炼厂数量来"增加收入"——钱包已经溢出。
- 不要加第二座车厂——已测，`own` 从 84 掉到 39。
