写于 2026-11-06 02:55。Arena.mmx，24000 ticks，六种子。

两次都低于基线。**回退。**

### 第一次失败的原因（A 完整）

`destroyed` 涨了 31%，但 `lost` 涨了 63%。seed 10 里我方**丢了 `GACNST`（建造场，$3000）**：

```
our_lost:  GACNSTx1@$3000=$3000 E1x8@$200=$1600 FVx1@$600=$600 GAPILLx1@$500=$500
```

威胁分布按造价加权后，一辆 HTNK 值 4.5 个 E1，`need` 被推高，军队过度出击，基地守备崩了。

### 第二次失败的原因（A1+A3）

去掉造价加权后好一些（1.7x → 2.118x），但仍不如基线。seed 24301 出现**负净效益**（−$1300）并再次丢建造场。

## 这次失败暴露了一个更根本的事实

我查了「建筑为什么从不成为攻击目标」，原以为是 `FireError::Illegal` 把它们剔除了。**不是。**

```
整场 Assault 次数：118
不同的 Assault 目标：1 个（id 1157，12 次）
整场 seen 计数：0 / 1 / 4
```

敌方有 26 个建筑、17 个单位。**军队全场只打过同一个目标，看见的从不超过 4 个。**

原因在代码里写得很清楚（`military.rs:563`）：

```rust
// What the house can see, not what the world holds. The projection's own
// enemy list is omniscient ... the spec forbids aiming at anything the
// player could not have clicked, so a target is something in line of
// sight right now. A house that sees nothing holds its post.
```

这是**设计约束**，不是缺陷：不许瞄准玩家点不到的东西。

所以阶段 A 和 C 全都建立在一个不成立的前提上——**「军队能看见敌方基地」**。侦察到不了 y≈130 的敌方基地，先前提到的那个「侦察兵反复换人、走一半折返」的缺陷，才是所有后续工作的前置。

## 结论

顺序要改。原计划 A → B → C，现在应当是：

1. **先修侦察兵**（让它真的抵达敌方基地并保持在那里）
2. 再谈威胁分布和打建筑

不修第 1 步，A 和 C 都在优化一个看不见战场的军队。

侦察兵缺陷的确切形态（已两次实测）：

- 同一场对局里侦察兵 id 换了 7 个（1154/1155/1225/1229/1262/1336/2749）
- 位置在 `(95,90) (83,51) (94,106) (83,39) (90,77)` 之间摆动，目标格 `(84,152)` 从不到达
- 视野本身正常（`visible_13x13` 有 86–169 格）
