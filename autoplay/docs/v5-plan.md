# v5 计划书：先划界，再实现

## 0. 为什么要有 v5

v4 不是失败，是**方向没划清**：

- 愿望清单（`G:\Documents\autoplay-v2.txt`，131 行、60 多个条目）被当成了路线图。它的条目互相依赖、边界模糊，做完一条会长出三条，于是"完成"永远无法定义。
- 与此同时，一个 22 文件、~1 MB 的策略（`sim/strategy/retail/`）住进了引擎 crate，成了游戏默认大脑。改一行策略要重编游戏，4,399 个应用测试里塞满了策略断言。
- 结果是：**autoplay 这个词同时指着两件相反的事** —— 玩家委托的托管（要求保守、可预测、零意外）和代替玩家打赢的 BOT（要求强、可以激进）。两者共用一套代码、一套验收，互相妥协。

v5 不做重写。**v5 只做一件事：把边界画对，然后把现有资产搬到边界的正确一侧。**

## 1. 新原则

1. **先划界，再实现。** 一个改动开始前，先说清它属于哪一层、谁验收。
2. **托管是薄层。** 它只做"玩家一定会做但不值得手动"的事；玩家一动就让位。目标 ≤ 500 行、≤ 6 条规则。
3. **BOT 是独立物。** 它代替玩家，可以激进；它不进入游戏的默认构建，用工具和 feature 驱动。
4. **验收跟着边界走。** 托管的验收是"零意外"，BOT 的验收是"功能 + 胜负"。**永远不拿 BOT 的尺子量托管。**
5. **愿望清单只当需求来源，不当验收。** 它列的是"想要什么"，不是"怎么算做完"。

## 2. 目标架构

```
vera20k (游戏)
├── sim/behavior  L1 执行        ← 保留，两者共用
└── sim/control   L2 控制        ← 保留，两者共用
    ├── Brain port（brain.rs）
    ├── 外部契约（external.rs）—— 留给以后的外部 BOT，本期不接
    └── sim/strategy/retail/    ← feature gate 掉（feature = "bot"），默认不编译

vera20k-autoplay (引擎之外)
├── assist.rs    托管：~300-500 行，游戏默认大脑
└── policy.rs    BOT：现有 v2 策略，默认不编译，autoplay-match / 工具驱动
```

关键点：

- **引擎不再长**：托管和 BOT 都是 `Brain` 实现，引擎只提供执行与准入。
- **构建解耦**：`sim/strategy/retail/` feature gate 之后，改策略不重编游戏。
- **两个大脑并存但不同时启用**：默认 `assist`，`VERA20K_BRAIN=bot` 才用 BOT。

## 3. 阶段

### P0 划界（先止血，1–2 天）

1. `sim/strategy/retail/` 加 `#[cfg(feature = "bot")]` 门；`sim/mod.rs` 相应声明。
2. 游戏默认大脑改为 `assist`（P1 完成前可暂留 `RetailBrain`，但要在代码里写明"过渡"）。
3. 把 v4 的 6 个未验证提交标注清楚（文档层面），不删。

**验收**：`cargo build --release` 正常；`cargo test -p vera20k-core --lib` 与 `-p vera20k --lib` 全绿；游戏可启动。

### P1 托管最小集（核心，3–5 天）

`autoplay/src/assist.rs`，6 条 reflex，每条一个测试：

| # | 触发 | 动作 | 不做什么 |
|---|---|---|---|
| 1 | 我方单位/建筑受击 | 就近战斗单位迎击 | 不出基地射程 |
| 2 | 建筑血量 < 30% | 自动卖 | 不卖 > 50% 的 |
| 3 | 钱 > 阈值 且 兵营/车厂空闲 | 按玩家已有比例补兵 | 不造新建筑 |
| 4 | 工程师/间谍路过可占领目标 | 顺手占领 | 不主动派兵去远处 |
| 5 | 单位残血 | 自动回维修 | 不离队太远 |
| 6 | 敌人进基地 | 鸣笛集合 | 不追击 |

**验收**（托管专用）：

- 玩家操作后 1 秒内停止一切托管动作；
- 单帧耗时 < 1 ms @ 1000 单位；
- 单局不花超过阈值的大钱、不送超过 N 个单位；
- 代码 ≤ 500 行，无地图分析、无寻路、无建造计划。

### P2 玩家可感知的开关（1–2 天）

- 热键域改为托管语义：**防守 / 生产 / 能力**（现在是 production/forces/abilities，语义接近，但要按"托管"重命名与文档化）。
- HUD 显示托管状态（哪个域开着、当前在做什么）。
- 每局独立（已有）、编队让位（已有）。

### P3 BOT 独立（1–2 周）

- `sim/strategy/retail/` 整体移入 `autoplay` crate（或独立 `bot` crate），引擎只留 L1/L2。
- BOT 的驱动：`autoplay-match`（无头打分）、`autoplay-replay`（录像分析）、可选的外部接口。
- BOT 验收沿用 `acceptance.md` 的 T1–T8 + 功能覆盖。

### P4 回归与清理

- 把 v4 停用的 sidebar 测试修好（25 个，签名问题，机械改）。
- 把 32 条历史问题做成回归清单，逐条跑图打勾。
- 删掉 v4 计划书里已被 v5 取代的部分（保留在 git 历史）。

## 4. 验收（v5 的"做完"定义）

| 层 | 标准 |
|---|---|
| 托管 | 零意外 + 性能 + ≤ 500 行；玩家不操作时也几乎不做事 |
| BOT | T1–T8 全绿 + 功能覆盖表不低于参照 |
| 构建 | 改托管不重编策略；改策略不重编游戏；两者都不影响对方 |
| 仓库 | lib 测试全绿；无停用测试（sidebar 那 25 个修好） |

## 5. 明确不做

- 不把 BOT 的战略（建造顺序、扩张、兵种相性、分基地、进攻时机）放进托管。
- 不用愿望清单逐条打勾当验收（它是需求池，不是验收单）。
- 不在本期接外部接口（`external.rs`）的传输层。
- 不碰 `E:\Projects\vera20k` 那条线。
- 不在托管里引入寻路/地图分析/计划层。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 1 MB 策略搬迁的可见性问题 | 先 feature gate（可逆），搬迁放到 P3，单独一个 PR |
| 托管"什么都不做"也算通过？ | 用场景测试：设定受击/残血/有钱三种局面，断言对应动作发生 |
| 两个大脑的默认值来回切 | 只允许一个默认（assist），BOT 只能显式启用 |
| 磁盘/构建时间 | 每次构建后 `--trim-cache`；E: 已有约 317 GB 空闲 |
| v4 的未验证改动被误当成基础 | 文档标注 + 测试覆盖；P4 之前不依赖它们 |
