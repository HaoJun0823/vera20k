# 第二十轮：隔离四项，并找到"永远赢不了"的机制

写于 2026-11-05 06:15。

## 逐项隔离 `012926859` 的四项改动

上一轮定位到该提交让 Barrel 从 5/6 掉到 0/6。本轮逐项关闭，看哪一项是元凶。

| 关闭的项 | Barrel |
|---|---|
| 主力军队不朝敌人平均方向走 | 0/6（无变化） |
| 侦察兵遇门口接触就停止 | 0/6（无变化） |
| **`far_target` 恒为 false** | **2/6**（seed 19 won 23751, seed 42 won 18701） |

**元凶是 `far_target`（"远处目标不再拴住强军队"）。**

## 但这一项在两张地图上效果相反

关闭 `far_target` 后：

| 地图 | 开启 | 关闭 |
|---|---|---|
| Barrel（小图） | 0/6 | **2/6** |
| Arena seed 19 | 127 | **59** |
| Arena seed 99 | 93 | 40 |

**Barrel 需要它关闭，Arena 需要它开启。**

上一轮试过"按地图尺度调整阈值"，结果更差（Barrel 仍 0，Arena seed 19 掉到 45）。
说明问题不在阈值大小，而在这条规则本身对不同地图的适配方式。

## 更重要的发现：`enemy=0` 却判 timeout

关闭 `far_target` 后 Arena seed 19 出现：

```
tick 23709   443   2544   215   59   0   0   0   0
```

**`enemy=0`，我方仍有 59，但结果仍是 timeout。**

查到了原因：`HouseState::game_alive` 的口径是
`active_units / active_infantry / active_aircraft` —— **只要还有任何单位就算活着**，
建筑全灭也不算被击败。

配合 `is_defeated` 只由 `mplayer_defeated` 置位，这意味着：

**只要敌方还有一个士兵在地图上，就永远不判定胜利。**

原版 RA2 用 `[Options] ShortGame=yes` 时只数基地单位（建筑），默认模式数全部单位。
所以这不是引擎 bug，是**默认模式的对战长度设定**。

### 这解释了两件长期困惑的事

1. `enemy=44` 在 48000 ticks 内几乎不降 —— 敌方一直在补单位
2. 我们的军队即使打到敌方基地，也赢不了 —— 需要逐个杀光每个单位

## 本轮没有功能改动

三项隔离都是临时探针，已全部回退。工作树干净，47 个测试通过。

## 下一轮

`far_target` 的正确修法不是调阈值，而是**让军队在两种情况下行为不同**：

- 小地图（基地近）：不越过，直接打
- 大地图（基地远）：越过，走向敌方基地方向

### 但两个地图尺度访问器都不可用（实测）

本轮加了诊断，实测两个访问器在两张地图上的取值：

| 地图 | `map_extent()`（fog 网格） | `ground_extent()`（LocalSize） |
|---|---|---|
| Arena.mmx | 160×160 | **70×69** |
| Barrel.mmx | 143×143 | **66×63** |

**`ground_extent` 也无法区分两张地图**（70 vs 66 只差 4 格），因为它取的是
`[Map] LocalSize=` 的局部矩形，不是全图。

`map_extent` 差 17 格（160 vs 143），**反而是更可用的判据**——虽然它是填充后的
缓冲区，但至少两张地图的取值不同。

所以上一轮用 `ground_extent` 调整阈值失败，原因不是"只调阈值"，而是
**这个访问器本身给出的是几乎相同的数**。

下一轮要判断"地图大小"，应该用 `map_extent`（fog 网格），它的绝对值不准但相对
差异可用；或者找引擎里真正的全图尺寸来源。
