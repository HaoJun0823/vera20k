# 功能实现计划（1v1 优先，多场景适配）

写于 2026-11-04 08:30。依据两份东西：许愿书 `G:\Documents\autoplay-v2.txt`（113 行），
和这一夜实测出来的九个失败尝试（`excluded.md`）。

## 零、两条前提

**前提一：功能与强度是两个轴，分开验收。**

| 轴 | lane | 判据 |
|---|---|---|
| 功能正确 | 1v1 easy（Death / Barrel / Oceansid） | 职位表里出现该 job，且日志能看出它做对了 |
| 强度 | 1v1 normal → hard | own / lost / 胜率 |
| 泛化 | 1v7 easy | 不整体崩就算过 |

1v7 从今天起是**回归报警器**，不是验收尺。理由有数：1v1 easy 我们 57 对 45（有余量），
1v7 easy 是 84 对 274（每个单位都承重）。这一夜九次改动全在 1v7 上被打回来，不是功能
错了，是那里没有余量。

**前提二：功能在动手前必须先定"它能触发"的 lane。**

这一夜有三个功能"实现了但从没触发过"：

| 功能 | 结果 |
|---|---|
| `route_is_clear`（占领途中避威胁） | 一次没拦下过 |
| `Illegal` 整队过滤 | `seen=21 reach=21`，过滤零次 |
| 驻扎（带闸门） | 1v7 零次 |

它们不算完成——没有一条读数证明它做对了事。**新功能必须先在目标 lane 上跑出非零
计数，才算交付。**

## 一、玩家无法参与生产（优先级最高）

### 现象

玩家点建造 cameo 提示 cannot。侧边栏的 `ObjectCameoDrawInputs.draw.enabled` 来自
`unavailable == 0`，而 `unavailable` 就是原版 `FindFactory(1,1,1)` + `CanBuild(type,0,0)`
的答案。

### 成因（已核实代码，未核实运行时）

原版 **一个工厂同时只能生产一种类型**：`Factory` 有 active build（持有一个 object、
progress、balance），队列里追加的是**同类型**的 `QueueEntry`（`factory.rs` 的
`arm`/append 分支，`max_queued` 上限在 `0x004C9CD5`）。

autoplay 的 `Military::produce` 每期都在往工厂里塞东西。工厂一旦被 bot 的类型占住，
玩家点另一种 cameo 时 `CanBuild` 回答 no，图标变灰、点了报 cannot。

**这不是引擎的 bug，是仲裁问题：两个主体在用同一个单类型槽位。**

### 方案取舍

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 让路** | bot 看到玩家最近的生产意图，就停止提议生产 N 秒 | 玩家完全无感 | 需要新增"玩家意图"观测 |
| B. 队列共存 | bot 往玩家队列里追加自己的一份 | 双方都在造 | 原版是单类型队列，要改引擎语义 |
| **C. 快捷键开关** | 玩家关掉"生产托管"，bot 不碰工厂 | 明确无歧义 | 要玩家动手 |
| D. 永远空闲才造 | bot 只在工厂空时提议 | 改动最小 | bot 产能腰斩（已测：单工厂是瓶颈之一） |

**推荐 A + C 组合**，因为 A 覆盖"忘了按开关"的日常，C 是玩家想彻底接管时的硬闸。

- **A** 需要的新观测：`player_production_intent`——玩家最近点过的 cameo 类型 + tick。
  这不是模拟状态，和已有的 `player_groups` 同类（"编队单位不参与托管"就是这么做的：
  控制组是玩家的承诺，`Observation::with_player_groups` 传进来）。
  实现位置：`Observation` 加一个传入口，`Military::produce` 在提议前检查。
  让路时长建议 30 秒（一个建造周期的量级），先给一个数，实测再调。
- **C** 对应许愿书限制 1：快捷键有全局/生产/战斗/能力。当前 `ATTACK_ENABLED` 是编译期
  常量，需要变成运行期状态。

### 验收

在实机里：玩家点建造 → 图标可用、能进入生产；bot 在 30 秒内不抢占。

## 二、功能清单，按可验证性分档

许愿书条目很多，但"能不能验证"差别巨大。按这个排，不按重要性排。

### 第一档：1v1 easy 立刻能触发

| 功能 | 现有状态 | 缺什么 | 验收读数 |
|---|---|---|---|
| **捡箱子** | 无（`crate` 零命中） | 需查投影有无 crate；`JobKind::Pickup` 新建 | 吃到箱子的计数 |
| **探索迷雾 / Scout** | `JobKind::Scout` 在枚举里、`manager()` 映射到 Military，**从不提议** | 提议逻辑 + 探哪里的选择 | `Scout` 非零 |
| **围墙** | 无（`wall` 零命中） | 建造链加围墙 rung + 放置位置 | `Placed building GAWALL` |
| **出售保不住的建筑** | 无（`Sell` 零命中） | 新命令路径 + 判定 | 卖出计数 |
| **分基地（MCV）** | 只有开局部署（`Roles::DEPLOYER`） | 第二个 MCV 的生产 + 选址 + 部署 | 第二座 `GACNST` |
| **子弹分配（V3 不溢出）** | 无 | 需要多单位协同选目标 | 同一目标并发数 |

### 第二档：需要特定地图或设置

| 功能 | 需要 | 备注 |
|---|---|---|
| **海上运输** | `Oceansid` / `Pacific` / `SeaofIso` | `JobKind::Transport` 在枚举里，从不提议 |
| **空中运输** | 运输机 + 陆图 | 同上 |
| **微操矿车** | 矿脉分布不均的图 | 现在矿车走默认寻路 |
| **风筝 / 躲避弹道 / 绕后** | **需要"打输的场面"** | easy 难度下我们不输，测不出；要先拉 normal |
| **打得过就打，打不过就跑** | 同上 | `JobKind::Retreat` 在枚举里，从不提议 |

### 第三档：被前置卡住，现在做不了

| 功能 | 卡在哪 |
|---|---|
| **超级武器使用** | 只造不用；且实验室 2000 元造不起（钱包峰值 ~1000，生产全额预扣） |
| **渗透**（工厂/矿厂/实验室/超武） | 需要 agent 单位 + 目标建筑，且要先解决经济 |
| **光棱 / 天启级兵种** | 同上，科技链断 |
| **克隆缸 / 回收厂 / 维修厂** | 三者在 autoplay 里零代码，要先建起来 |
| **感染 / 寄生处理** | 需要能触发感染的敌方单位 |
| **英雄单位保护** | 需要限制建造的英雄位 |
| **建筑特殊能力**（生化电厂等） | 无 |
| **心灵控制回收中立载具** | 需要 Yuri 单位 |
| **切换主生产工厂** | 无 |
| **建筑分散布置防超武** | 无 |

### 一条与许愿书冲突、必须先解决的

许愿书「建造单位」只有一句「会根据战斗情况和单位特点生产各种单位」，但实测出来的
组成是 **33 狗 / 33 GGI / 25 E1 / 10 IFV / 5 灰熊**——这是按角色配比平均买的必然结果，
而 62% 的战损正是那批打不动装甲的。

**"按配比买"和"屯一种兵"是互斥的。** 屯灰熊（你说的第一档打法）要求放弃多样性，
这是功能层的改动，会直接影响强度轴，所以要排在功能轴之后、强度轴之前做。
