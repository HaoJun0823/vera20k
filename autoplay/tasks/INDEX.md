# 子任务总表

**接手先读**：[`../DESIGN.md`](../DESIGN.md)（目标、验收源、分层、当前进度）→ 本表 → 你要做的那张卡。
卡是自包含的，不需要读历史对话。所有状态在 git 里，不靠会话记忆。

**状态**：`待办` / `进行中` / `已完成`。标「已完成」必须附**提交号 + 实测数字**。
**任何中断收尾必写四项**：做到哪、下一张卡是哪张、实测数字、未决项。改状态就改本表，
与代码同批提交。

## 4. 新建卡的模板

复制到 `tasks/TNN-short-name.md`，8 项填满才允许标「进行中」。

```markdown
# TNN 卡名

| 项 | 值 |
|---|---|
| 状态 | 待办 / 进行中 / 已完成 |
| 层 | 1 战略 / 2 队伍 / 3 战术微操 / 4 单位意图与执行 |
| 依赖 | 无 / Txx |
| 负责人 | （留空，谁领谁填） |
| 完成证据 | 提交号 + 实测数字（完成时填） |

## 1 要做什么
一句大白话。

## 2 游戏里能看到什么
看得见的变化，不是「内部更清晰」。

## 3 合格线（可数）
可数的判据，不写「良好」「充分」。含基线数字与预期数字。

## 4 不许复发
对应 DESIGN.md §3 的 P 编号，逐条说明本卡怎么保证不复发。

## 5 依赖与前置事实
已知坑、实测结论、为什么必须先做依赖卡。

## 6 验证命令
一条能复现的命令 + 预期输出。

## 7 接口边界
只能碰哪些文件/模块；明确不许碰哪些；一个状态一个主人。

## 8 收尾要写什么
做到哪、下一张卡、实测数字、未决项（并同步更新本表状态）。
```
