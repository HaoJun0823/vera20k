**本设计统一为下面一套**，两套旧编号都映射到它。

| 层 | 回答什么 | 旧编号 | v3 现有模块归位 | 游戏里能看到什么 |
|---|---|---|---|---|
| **1 战略** | 造什么、经济、科技、开分基地 | 四层 L1 | **空** | 会按需补电厂/矿厂/兵种、开分矿 |
| **2 队伍** | 编队、角色、目标锁 | 四层 L2 | **空** | 成建制的小队一起行动 |
| **3 战术微操** | 接战/撤退/绕路/占领/渗透/风筝 | 四层 L3 | `frame.rs` 仅「打最近的可见敌人」(`a1ed68461`) | 会打也会撤，不排队送死 |
| **4 单位意图与执行** | 追踪式下令、准入、任务跟踪 | 四层 L4 + 三层 L1/L2/L3 | `control.rs` `arbiter.rs` `eligibility.rs` `claims.rs` `executor.rs` `dispatch.rs` `replan.rs` `observe.rs` `handover.rs` `idle.rs` `frame.rs` `world.rs` `trace.rs` `ledger.rs` `availability.rs`；客户端 `src/app/match_runtime/sim_tick.rs`、`src/app/input/hotkeys*` | 命令不重复发、单位不挂机、每步可解释 |
| **底座** | 引擎原生 | — | `vera20k-core`：`Command`、`Snapshot` 读取的引擎状态、fog、原生队伍 AI | — |

**铁律**（违反即打回）：

1. 单向依赖：下层不命名上层；`sim/` 不依赖 `render/` `ui/` `audio/` `net/`。
2. **一个状态一个主人**：不建引擎已拥有状态的第二份副本；`Snapshot` 一次读取后是不可变值。
3. 所有改变游戏状态的命令经 `Arbiter::admit` → `issue_local_command` 走**玩家同一条命令通道**；
   不直接写仿真状态。
4. **不作弊**：只用 `Snapshot::enemy_visible()`，不用引擎全知的 `enemy()`；
   静态地图信息（L0）不能冒充实时视野（L2）。
5. 规则驱动，不写死单位名；单位能力从 rules 推导，便于 ares/phobos/mod 扩展。
6. 每个决策可解释（`Trace` 记录全部候选、赢家、理由），每个拒绝具名。
7. 每步可独立验收，不许一次性重写全部系统（架构书 §20.14 / §20.15）。

## 6. 协作规则（多个开发者 / 任意中断接手）

### 接手流程

1. 读本文件（目标、分层、验收源、当前进度）。
2. 读 [`tasks/INDEX.md`](tasks/INDEX.md) 总表，看哪张卡状态是「待办」且依赖已满足。
3. 读那一张卡。**卡是自包含的**，不需要读历史对话。
4. 跑卡里的「验证命令」建立基线，再动手。

### 每张卡固定 8 项

编号/状态 · 依赖 · 要做什么 · **游戏里能看到什么** · 合格线（可数） ·
不许复发（对应 §3 编号） · 验证命令 · 接口边界（能碰/不能碰哪些模块）。

### 状态与收尾

- 状态只有 `待办` / `进行中` / `已完成`。标「已完成」必须附**提交号 + 实测数字**。
- **每次收尾必写四项**：做到哪、下一张卡是哪张、实测数字、未决项。不写不结束。
- 改了结论就改 `DESIGN.md`；改了状态就改 `INDEX.md`。两者与代码同批提交。
- 状态全部在 git 里，不放在 `.codebuddy/`、不靠会话记忆或 handoff 碎片。
- 中断后任何人接手，只需 `git log -1` + 本文件 + `INDEX.md` + 那张卡。

### 施工顺序

按架构书 `G:/Documents/autoplay-v3.txt` §19 的 Phase 0–6 推进，但**范围以许愿书为准，
不受 `plan.md` §10 裁剪约束**。当前在 Phase 2（任务系统）收尾与 Phase 4（基础战术）第一刀。
具体卡片与依赖见 `tasks/INDEX.md`。

cd E:\Projects\vera20k-autoplay-v3
